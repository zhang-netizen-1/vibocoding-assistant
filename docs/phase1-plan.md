1. 在新分支 `phase1-skeleton` 上开发，按第 3 节的步骤一步一个提交。**不要推送、不要合并到 main**（推送 main 会触发 GitHub Pages 发布）。合并要等主人验收。

## 2. 新网址规则

| 栏目 | 栏目页 | 条目页 |
|---|---|---|
| 首页 | `/` | — |
| 设计基础 | `/basics/` | `/basics/<slug>/` |
| 组件 | `/components/` | `/components/<slug>/` |
| 交互与动效 | `/interactions/` | `/interactions/<slug>/`（交互规则 7 + 动效 77） |
| 交互与动效 · 实现规范 | `/interactions/spec/` | 页内锚点沿用原来的 `#spec-*` |
| 页面与场景 | `/scenarios/` | `/scenarios/<slug>/` |
| AI 实现 | `/ai/` | `/ai/skills/<slug>/` |
| 测评结果 | `/bench/`（**不搬家**，地址不变） | `/bench/button/` 等不变 |

- 栏目分组锚点：`/components/#group-<分组 slug>`。
- 新路径故意不和旧路径重名（如新的是 `/interactions/`，旧的是 `/interaction/`），这样旧路径可以整页做成跳转页，不会互相覆盖。
- `slug` 由旧锚点去掉前缀得到：`c-button` → `button`；`e-view-crossfade` → `view-crossfade`；`e-extra-<x>` → `<x>`；`g-layout-grid` → `grid`（去掉 `g-<旧栏目>-`）；`skill-frontend-design` → `frontend-design`。同一栏目内 slug 重复时构建报错，由人工在映射表里指定。

## 4. 旧地址和旧锚点怎么跳转

GitHub Pages 不支持服务器端跳转，而且浏览器不会把 `#锚点` 发给服务器，所以用「跳转页 + 页内脚本」：

1. 8 个旧栏目路径 `/ui/`、`/motion/`、`/layout/`、`/visual/`、`/interaction/`、`/pages/`、`/data/`、`/skills/` 的 `index.html` 改成很小的跳转页。
2. 跳转页里内嵌该栏目的「旧锚点 → 新地址」表，由 `taxonomy.json` 生成。脚本读 `location.hash`：
   - 是条目锚点（`#c-button`）→ `location.replace('/components/button/')`；
   - 是分组锚点（`#section-view`）→ 新栏目页的分组锚点（`/interactions/#group-view`）；
   - 是实现规范锚点（`#spec-*`）→ `/interactions/spec/#spec-*`；
   - 没有锚点或查不到 → 该旧栏目对应的新栏目页（如 `/ui/` → `/components/`）。
   - 用 `location.replace`，不在浏览器历史里多留一步。
3. 关闭了 JS 的情况：`<noscript>` 里给「本页已搬到 ××」的链接，并用 `<meta http-equiv="refresh">` 跳到新栏目页（这种情况锚点会丢，可以接受）。
4. 合并条目（D2）：
   - `/motion/#e-extra-submit-flow`（提交反馈状态链）和 `/interaction/#g-interaction-submit`（提交状态链）→ 同一个新页 `/interactions/submit/`；
   - `/motion/#e-extra-delete-undo`（删除退出与撤销）和 `/interaction/#g-interaction-undo`（撤销操作）→ `/interactions/undo/`。
5. 搬到别的栏目的条目按 PRD 5.4 走，例如 `/ui/#c-auto-save` → `/interactions/auto-save/`，`/ui/#c-cmdk` → `/components/cmdk/`，`/data/` 里的可排序数据表 → `/components/` 下的对应条目。
6. `/motion/motion-demo-gallery.html` 和 `/motion/motion-demo-detail.html` 原样保留在原路径。
7. `/bench/` 不搬家，所以不需要跳转。

## 5. 怎么验证

**构建时自动检查**（写进 `tests/test_site_build.py`，失败就不能构建，也就不会发布）

- 条目总数 187；各栏目、分组条数等于 PRD 5.3；同栏目内 slug 唯一。
- `tests/fixtures/old_anchors.json` 里的每个旧锚点都在跳转表里，目标页面真实存在。
- 页面里不出现「189」「INTERFACE FIELD GUIDE」等旧文字；不出现深色主题样式。
- 演示区样式里不出现 `#1D4ED8`；外框样式只用 PRD 15.3 表里的颜色。
- 用 `docs/style-research/contrast.py` 的公式检查 15.3 表里每一对颜色的对比度。
- 现有 `test_site_build.py` 里写死的「189 条」「10 个页面」和文件清单要同步改成新结构，不能直接删测试。

**无界面浏览器检查**（脚本放 `tests/e2e/`，本机跑）

- 首页、5 个栏目页、全部 187 个条目页，在 1440 / 768 / 390 三种宽度下：无整页横向溢出，没有脚本报错。
- 每个条目页不滚动就能点到「复制提示词」；复制内容和页面上的提示词一致，有验收要求的条目包含全部验收要求。
- 搜索：任意页 `/` 和 `Ctrl+K` 打开；↑↓、Enter、Esc 可用，关闭后焦点回原处；结果行复制可用；搜「霓虹灯」出现无结果三块且没有反馈入口。
- 大下拉：只有分组和条数；键盘可开关，Esc 后焦点回栏目按钮。
- 手机抽屉：从右侧滑出、背景不滚动、Esc 和遮罩可关、焦点回「目录」。
- 栏目页演示格：不悬停时没有动画在播放；悬停或聚焦才播放；减弱动态模式下完全不播放。
- 10 个状态切换条目：每个状态都能切换并固定显示。
- 互链：映射表里每一对，两边页面都有链接且能打开。
- 189 个旧锚点逐个打开，最终地址正确；8 个旧栏目路径不带锚点时跳到对应新栏目页。
- 站内所有链接返回 200。

**人工检查**：第 6 步和第 13 步各给主人一次截图，主人认可后才继续或合并。

## 6. 风险和对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 演示原来挤在一张大页面里，样式和脚本互相依赖，拆成单页后可能失效 | 部分演示不动或错位 | 第 3 步先体检分类；条目页引入原来的演示样式和脚本包；需要 JS 的演示在格子进入视野或悬停时才初始化；逐页无界面检查有没有报错 |
| 列表里 70 多个演示同时存在，页面变卡 | 栏目页卡顿 | 默认全部暂停；同一时间只播放一个格子；需要 JS 的演示懒加载 |
| 依赖鼠标的演示（光标跟随等）在手机上没法看 | 手机上看不懂 | 用「▶ 播放」自动演示一遍，或写一句替代说明（第 3 步体检时标出来） |
| 旧链接失效 | README、测评页、分享出去的链接打不开 | 第 4 节跳转页 + 189 个锚点逐个测试 |
| 关闭 JS 时锚点丢失 | 只能跳到栏目页 | 可以接受，在 noscript 里写清楚 |
| 页面从 10 个变成约 200 个，构建变慢、文件变多 | 构建时间 | 一个模板循环生成，文件清单由数据算出，不手写 |
| 一期改动面大 | 合并时难以发现问题 | 分 13 步提交；两个主人检查点；不推送 main |
| 现有测试写死 189 和文件清单 | 测试先挂 | 第 2 步同步改测试，改成从数据计算 |
